For agents

A closed vocabulary, a JSON Schema, and errors written to be recovered from

prism is built to be driven by a language model. The agent does the part models are good at — reading prose and deciding what shape the idea has — and prism does the part models are bad at: geometry, spacing, alignment and colour.

prism itself never calls a model. It is deterministic: the same spec always produces byte-identical SVG.

The envelope

Every spec is a YAML mapping whose top-level type selects an archetype.

type: flow                   # required — one of the ten archetypes
theme: default               # bundled name, or a path to your own YAML
title: "Ingestion pipeline"  # optional
subtitle: "as of Q3"         # optional
caption: "Source: review"    # optional
width: 900                   # layout hint in px; height follows the content
tokens:                      # optional per-spec theme overrides, dotted paths
  palette.ink: "#0b1020"

Everything else in the mapping is the archetype’s own payload.

The shared node

Every archetype consumes the same node shape. This is the vocabulary worth memorising, because it is the same in all ten:

id: ingest                 # optional; needed only when something references it
label: "Ingest"            # required
sublabel: "S3 + Kafka"     # optional
icon: database             # optional; a Lucide icon name
badge: "1"                 # optional; at most 4 characters
accent: 2                  # optional; ramp index 0-5, or a palette token name
emphasis: normal           # strong | normal | muted
note: "runs nightly"       # optional; `flow` and `timeline` only

A badge is a short marker — a step number, a version, a count — drawn as a filled pill inside the top-right of the node. Four characters is the cap, so it never wraps. Every archetype that draws a node box draws its badge.

A note is a marginal annotation: muted, small, and set outside the node, below it in a left-to-right layout and beside it in a top-down one. Only flow and timeline have a free margin to put one in; on the other eight archetypes a note raises an error rather than being silently dropped, so an agent that emits one gets told instead of shipping a picture that quietly lost it. Fold the text into sublabel there.

Getting the schema

prism schema flow

emits JSON Schema for the archetype’s payload, suitable for structured output or a tool definition. Every archetype rejects unknown fields, so a typo fails loudly at validation rather than silently rendering the wrong picture.

An unknown icon name fails with a suggestion rather than rendering a blank.

Errors are part of the interface

prism’s exceptions are written for a recovery loop, not for a stack trace. Each one names the offending value and points at the valid neighbours:

unknown icon 'databse' — did you mean: database, data-flow?
unknown archetype 'flowchart' — did you mean: flow?
unknown token 'palette.inc' — did you mean: palette.ink, palette.line?
cell references unknown row 'emae'; known rows: ['emea', 'amer', 'apac']
era 'Pre-revenue' spans unknown event id(s) ['sed']; known ids: ['seed', 'beta']

An agent’s ability to fix its own output is bounded by the quality of the error string, so this is treated as a feature surface rather than as diagnostics.

Choosing an archetype

The decision is about the shape of the meaning, not the subject matter:

If the content is… Use
ordered steps, a process, a pipeline flow
containment or reporting structure hierarchy
a process that returns to its start cycle
events in time timeline
two or more options weighed against each other comparison
items placed against two independent dimensions quadrant
layers of magnitude, or stages that shed volume pyramid
tiers of a system, bottom to top stack
one centre with several dependents hub
values at the intersection of two lists matrix

When two fit, prefer the one with fewer nodes on screen.
